# MiniCode 初步设计

本文记录当前设计方向。实现细节可在相应阶段调整，重要变化应说明理由。

## MVP 与边界

MVP（最小可行产品）的目标：在指定项目中理解一个小型修改任务，读取相关文件，提出修改，经用户确认后写入，执行批准的测试命令，并汇报结果。

第一版采用单用户、单项目、单模型、同步顺序执行。会话只保存在进程内；退出后不恢复。核心 Agent Loop 自行实现。

暂缓复杂全屏界面、多 Agent、后台任务、多模型切换、向量数据库、长期记忆、插件，以及自动 Git 提交和推送。

## 核心组件

| 组件 | 职责 |
| --- | --- |
| CLI（终端入口） | 收集输入，展示结果与授权问题 |
| Agent Loop（循环控制器） | 调用模型、处理工具请求、执行停止规则 |
| Model Client（模型客户端） | 与模型服务通信，解析回复和工具请求 |
| Session（会话状态） | 保存消息、工具结果和执行计数 |
| Tool Registry（工具注册表） | 保存工具名称、参数说明和对应函数 |
| Tools（工具） | 读取、搜索、编辑文件，执行命令 |
| Permission Policy（权限规则） | 判断允许、拒绝或需要用户确认 |

初期用简单函数和数据结构表达职责，不要求每个组件都设计成类。计划中的模块包括 `cli.py`、`config.py`、`models.py`、`session.py`、`llm.py`、`agent.py`、`permissions.py` 和 `tools/`，随功能加入，不提前创建空壳。

`models.py` 表达内部数据结构，`llm.py` 负责外部模型调用。可安装代码放在 `src/minicode/`，测试放在 `tests/`。

## Agent Loop 的运行过程

1. 将用户输入加入会话。
2. 将消息和工具说明交给模型。
3. 模型返回最终回复，或者结构化的工具请求。Function Calling 表示工具请求，本身不执行函数。
4. 校验工具名称与参数，检查安全边界和权限。
5. 必要时请求用户确认；拒绝时生成明确的拒绝结果。
6. 执行获准工具，将结果与请求标识对应后加入会话。
7. 再次调用模型，根据结果继续行动。
8. 返回最终回复或停止原因。

消息区分用户、助手和工具；应用规则单独提供。一次返回多个工具请求时按顺序处理。工具结果应能表达成功、失败、拒绝和输出截断。

停止条件包括模型给出最终回复、调用次数达到上限、连续失败达到上限、模型请求无法继续，以及用户中断。达到限制不等于任务成功，必须说明未完成状态。具体上限在实现阶段确定。

## 安全边界

- 读取与搜索限制在项目范围，默认排除敏感文件并限制内容大小。
- 编辑需展示路径与差异，逐次确认；写入前检查外部修改，避免覆盖。
- 命令需展示参数、工作目录和超时，逐次确认；收集退出码、标准输出与标准错误。
- 初版不提供独立删除工具或自主 Git 提交、推送工具。
- 文件和命令输出只是数据，不能覆盖权限规则。
- 命令的工作目录不能限制程序的全部文件或网络访问。初版不是安全沙箱，仅面向用户监督下的可信项目；隔离执行另行设计。

## 技术选择

| 技术 | 初步选择与理由 |
| --- | --- |
| 语言 | Python 3.11+；已在 Python 3.12.3 验证 |
| 环境 | `venv` 与 `pip`，先掌握环境和依赖基础 |
| 配置 | `pyproject.toml`，在创建程序骨架时加入 |
| 模型通信 | HTTPX 同步调用 DeepSeek `/chat/completions`；默认 `deepseek-flash`，非流式、关闭思考模式，每次最多输出 1024 tokens |
| 模型配置 | python-dotenv 读取当前工作目录 `.env`，已有环境变量优先；配置密钥、模型、HTTPS 基础地址与网络操作超时 |
| 内部数据 | 优先标准库 `dataclasses` 和简单类型标注 |
| 多轮会话 | `Session` 按成功轮次保存 user / assistant / tool 消息；请求使用历史深拷贝，按整轮裁剪旧历史以满足上下文字节预算；成功后提交裁剪并记录本轮，纯只读失败不修改历史，有文件/命令影响或拒绝的停止另存完整交接；`/clear` 清空，退出不持久化 |
| 文件与命令 | `pathlib` 和 `subprocess` |
| 测试 | pytest；模型响应默认使用可控的测试替身 |
| 终端 | 先使用 `input()` 和 `print()`，之后再改善交互 |
| 版本管理 | Git，阶段性练习分支和 PR |

暂不引入异步框架、数据库、通用多服务商适配层或完整 Agent 框架。

## 第一阶段验收标准

第一阶段不接模型 API，不执行用户项目文件操作。

- 在独立虚拟环境中可以安装项目。
- `python -m minicode` 可以启动。
- 普通输入得到明确提示，说明模型功能尚未接入，并继续等待。
- 空白输入不产生任务；`/exit` 和 EOF 正常退出。
- Ctrl+C 结束程序并给出简短提示，不展示异常堆栈。
- 自动化测试覆盖以上行为；`python -m pytest` 通过且无需网络或密钥。
- README 中的安装、启动、测试命令经过实际验证。
- 提交前检查差异，排除密钥、缓存和虚拟环境。

## 第二阶段验收标准

- 从当前目录 `.env` 或环境变量读取 DeepSeek 配置，已有环境变量优先；不展示密钥。
- 输入问题后，以同步 HTTP 请求发送当前问题并展示文本回答，不保留对话历史。
- 空白和退出不发请求；等待模型时 Ctrl+C 可以正常结束程序。
- 缺少密钥、无效配置、超时、网络和 HTTP 服务错误有简短提示；失败后可以继续输入，不自动重试。
- 响应格式错误、空回答、长度截断或其他非正常结束不可作为完整回答显示。
- 自动化测试使用模拟响应，不访问真实 API、不读取用户密钥；真实调用单独验证。

接口依据：[官方快速开始](https://api-docs.deepseek.com/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)、[错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。

## 第三阶段验收标准

- 每次启动创建独立的进程内会话；第二轮请求按顺序包含上一轮用户问题、助手回答和当前问题。
- 仅在模型成功返回完整文本后保存整轮；配置、网络、服务或响应错误不留下未完成的问答，之前的成功历史不丢失。
- 构造请求使用消息副本，外部修改请求不会改变已保存历史。
- `/clear` 清空本地历史，不读取配置、不请求模型；空历史也可反复清空。
- 空白、清空和退出命令不进入历史；退出后不写入磁盘、不恢复会话。
- 离线测试直接检查 HTTP 请求的消息列表，覆盖多轮顺序、失败后继续、清空后新对话和重新启动。
- 第三阶段完成时不裁剪历史、不计算 token；第七阶段第二步已增加按整轮裁剪的上下文字节预算。

## 第四阶段：受限文件读取

- `tools/files.py` 提供 `read_file(project_root, relative_path) -> str`，失败抛出 `FileReadError`，不直接接入 CLI、会话或模型。
- 显式指定已存在的项目根目录；仅接受非空相对路径，解析真实路径后检查目录边界。允许仍位于项目内的符号链接，拒绝越界链接。
- 对原始相对路径及解析后的项目内路径逐段检查默认敏感名单，匹配不区分大小写。包括 `.env`、`.env.*`、Git 元数据、常见凭据目录、私钥名称和密钥后缀；具体名单集中在源码中。
- 仅读取普通 UTF-8 文本，保留空白；空文件合法，含空字节或无效编码拒绝。初版不是通用二进制文件检测器。
- 读取和返回上限均为 64 KiB；先检查文件大小，再最多读取上限加一个字节，超限明确失败，不截断后当作完整文件返回。
- 测试覆盖正常读取、空文件、大小边界、非法路径、越界、内部与外部链接、敏感别名、失效或循环链接、目录、特殊文件、权限错误和编码错误；无需模型或真实密钥。
- 默认排除名单不能识别所有秘密；真实路径校验不能防御并发恶意替换父目录等竞争，不作为安全沙箱。本阶段面向可信项目。
- 目前不发送文件内容到模型；后续工具接入时需在交互中明确告知这一数据流向。

## 第五阶段：工具注册与模型工具协议

- `tools/registry.py` 显式注册 `read_file`，`tool_definitions()` 返回新的工具说明及 JSON Schema。工具说明只是帮助模型生成请求，程序仍独立校验名称、JSON 对象及唯一的字符串参数 `relative_path`。
- `models.py` 的 `ToolCall` 保存请求编号、名称和原始 JSON 参数字符串；`ModelReply` 保存文本及有序请求元组。`as_message()` 构造新的 assistant 消息，不共享可变嵌套结构。
- `llm.request_model()` 每次只发起一次同步请求，返回 `ModelReply`；仅在显式 `use_tools=True` 时发送工具说明及 `tool_choice=auto`。原 `ask_model()` 保留纯文本返回值，不开放工具，CLI 继续使用它。
- 整批工具请求先完成协议检查：请求编号非空且不重复、类型为 function、名称非空、参数为字符串；拒绝缺失字段、格式异常、非正常结束及结束标志冲突，不执行任何工具。
- 未知工具及参数 JSON 内容错误由分发层返回工具错误；协议层只保留参数字符串，不把模型响应直接当作可执行函数。
- `dispatch_tool_calls()` 对解析后的请求顺序分发；单个工具错误产生结果后继续处理下一项。`ToolResult.as_message()` 生成 role=tool、tool_call_id 和 JSON 文本，JSON 中明确区分 status 与 content。空文件是成功结果。
- 先保留 assistant 的完整工具请求消息，再追加每项 tool 结果，才能构造后续模型请求。模型客户端本身不执行工具、不自动续问、不更新 Session。
- 验收采用离线 HTTP 模拟及临时文件，覆盖文本兼容、工具说明、协议错误、顺序执行、结果对应及手动发起下一次模型请求。真实 API 与 CLI 工具执行尚未验证；下一阶段再加入循环、会话整轮记录、数据流向提示及停止限制。

接口依据：[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。当前使用非流式、关闭思考模式的工具请求，未启用 Beta strict 模式。


## 第六阶段：Agent Loop

- `agent.run_agent()` 用同步循环连接 `request_model()` 和 `dispatch_tool()`，仅使用现有只读工具，不新增框架或依赖。应用规则通过独立 system 消息提供，不写入历史；工具和文件内容仅是数据，实际权限仍由程序检查。
- CLI 将启动时当前目录解析为项目根目录并展示；输入第一个问题前明确提示问题、成功历史、工具请求和读取内容将发送到配置的模型服务，默认敏感路径排除不能识别全部秘密。配置仍在每次提问时读取。
- 循环先保存 assistant 请求消息，再顺序校验、执行每个工具并追加对应 tool 结果，再次请求模型。单次工具错误可以交给模型纠正；空文件算成功。
- 每轮默认最多 8 次模型调用、16 次工具调用，连续 3 次工具错误停止。失败计数跨模型批次累积，成功工具会重置；模型请求错误立即停止，不重试。计数每轮重置，由 `AgentResult` 返回状态、最终回答或停止原因及模型/工具次数。
- 模型最终回答可在第 8 次返回；若最后一次回复仍要求工具，不再读取。整批请求超出剩余工具预算时全部不执行；连续失败触发时停止当前批次后续工具。
- `Session.record_messages()` 仅在最终回答成功后记录本轮全部 user / assistant / tool 消息；存入和取出均深拷贝，避免嵌套工具参数被外部修改。网络、协议错误、次数限制及中断不保存当前轮，保留此前成功历史。中断由 CLI 捕获并退出。
- 本阶段只有读取，无写入或命令副作用；丢弃未完成历史不代表撤回已经发给服务的数据，也不代表以后能撤销工具副作用。新增写入工具时需重新设计失败记录策略。
- 验收：离线模拟 HTTP 验证连续及批量工具调用、完整消息顺序和下一轮历史、错误恢复、各项限制、深拷贝、CLI 数据提示、清空与中断。真实 API、搜索、上下文裁剪、编辑、命令及持久化日志不在本阶段范围。


## 第七阶段第一步：项目搜索

- `tools/search.py` 提供 `search_project(project_root, query, relative_path=".") -> dict`，失败抛出 `SearchError`；注册为模型只读工具，复用现有 Agent Loop，不新增依赖。
- 字面、区分大小写搜索；query 为非空、至多 200 字符的单行文本。目录只接受项目内相对路径，对请求路径及解析后的路径检查现有敏感名单。显式目录可以解析到项目内目录；递归过程中跳过所有符号链接，不跟随链接目录。
- 复用 `read_file` 的普通文件、64 KiB、UTF-8、空字节及路径检查；敏感路径、常见依赖和缓存目录直接跳过。不解析 `.gitignore`，不支持正则、文件名搜索或大小写选项。
- 每次至多遍历 2000 条目、尝试读取 200 文件、返回 50 匹配行；结果 JSON 至多 16 KiB（外层工具消息另计）。每行返回相对路径、1 起始行号、至多 300 字符的首次匹配片段及片段截断标记。
- 结果包含 `scanned_files`（读取尝试数）、`skipped_entries`（被跳过的条目数，不展开排除目录）、`truncated` 及 `limit`。达到资源上限提前停止明确标记；无匹配仍为成功，不能将部分扫描断言为全项目无匹配。遍历顺序不保证排序。
- 验收使用临时目录和模拟 HTTP，验证定位、非法参数、安全边界、跳过条目、所有资源上限，以及搜索后读取并保存整轮历史。CLI 数据提示覆盖搜索片段。
- 本步仅控制单次搜索，不裁剪会话、不计算 token、不限制总上下文；上述功能留给第七阶段第二步。真实 API 验证另行进行。


## 第七阶段第二步：上下文限制

- `context.py` 提供 `context_bytes()` 和 `select_context()`。默认每次请求的上下文上限是 128 KiB，按包含 `messages` 和 `tools` 的紧凑 UTF-8 JSON 计量，包含系统提示、完整工具请求及结果、工具说明和转义开销。不是模型 token 计数，也不包含模型名称等其他参数或响应。
- `Session` 改为按成功轮次分组保存，`history_turns()` 返回深拷贝，原 `messages_for()`、`record_turn()` 接口保持兼容。`record_messages(..., discard_oldest_turns=N)` 在成功保存本轮时同时移除最早 N 轮。
- 每次调用模型前，从最早完整历史轮次开始省略，保留最新的连续后缀，不改变本轮消息。发生省略时向模型补充提示，提示计入预算，同一轮后续请求不重新加入已省略历史。工具请求与对应结果保持完整。
- 无历史仍超限时，`ContextLimitError` 使循环在下一次网络请求前停止；不截断文本、不拆消息，不自动请求摘要。可能已执行只读工具，但不再发送本轮新结果。模型调用计数仅在通过上下文检查、准备调用客户端时递增。
- 裁剪是事务性的：只有最终回答成功后修改 Session；网络/协议错误、停止及中断保留原历史。`AgentResult.omitted_history_turns` 返回本轮请求实际省略的旧轮次数，CLI 展示成功移除或失败保留的区别。
- Python `run_agent` 支持正整数 `max_context_bytes`，CLI 固定默认值，底层 `request_model` / `ask_model` 不自动施加此策略。最终回答在请求后保存，因此不承诺 Session 内存硬上限；下一轮再检查。字节预算不保证满足服务端 token 限制。
- 验收：UTF-8 与 JSON 转义、工具说明及系统提示的计量、精确边界、最早整轮移除、完整工具消息、首次请求及工具结果后的超限、跨多次请求稳定省略、成功提交与失败/中断保留、CLI 提示；全部离线验证。


## 第八阶段第一步：只读修改预览

- `tools/edit.py` 提供 `preview_edit(project_root, relative_path, old_text, new_text) -> EditPreview` 和 `EditPreviewError`；本步不注册模型工具、不接入 CLI 确认、不写入文件，不提前改变 Agent Loop 的失败历史策略。
- 使用冻结 dataclass 保存请求相对路径、完整修改前后文本和统一差异；这是读取时快照，不代表授权，未来写入仍须重新校验路径、用户确认及外部修改。
- 复用 `read_file` 的项目真实路径边界、请求与解析路径敏感检查、普通 UTF-8、空字节及 64 KiB 限制，项目内符号链接可只读预览。读取错误转成不含正文的 `EditPreviewError`。
- 原文本非空，按大小写、空白和换行精确匹配一处，包含重叠的多处匹配也拒绝；替换文本可为空。原文和新文本相同则拒绝。只替换一处，不创建或删除文件，不支持正则、多文件或批量操作。
- 输入文本各至多 64 KiB，拒绝空字节和不能编码为 UTF-8 的字符串；修改后完整文件至多 64 KiB，差异至多 128 KiB。差异包含相对路径、行号和默认三行上下文，路径用 JSON 引号转义，缺少末尾换行单独标记；超限报错，不截断。
- 验收采用临时项目验证输入到差异的完整流程、安全与错误边界、大小上限和不可变快照；所有成功/失败预览均不改变原文件。真实模型、写入、确认和冲突处理留给后续小功能。


## 第八阶段第二步：逐次确认与安全写入

- 扩展 `EditPreview`，绑定解析后的根目录、目标路径和文件状态签名；生成预览时核对读取前后状态。`files._resolve_file_path()` 提取既有路径检查供读写共同复用，读取的原有权限和大小行为不变。
- `apply_edit(project_root, preview, *, confirm) -> EditApplyResult` 要求应用提供可信确认函数，不能由模型设置布尔授权参数。重新校验原/新文本、大小和差异一致性，在确认前、确认后及临时文件准备后检查项目、路径、原文字节、设备/inode、大小、mtime/ctime、权限、属主和链接数。
- `permissions.confirm_edit(preview)` 展示解析后的项目根目录、相对路径和完整差异，控制字符仅在展示时转义。只接受终端 y/yes，默认拒绝，EOF 拒绝，中断向外传递，每次重新询问。apply 层只接受回调严格返回 True。
- 拒绝返回 denied 且不创建临时文件；冲突/错误抛出 EditConflictError/EditApplyError。确认通过后在同目录创建临时文件、完整写入 UTF-8、保留普通权限位、flush/fsync，最后检查后用 os.replace 替换，成功返回 applied。失败或中断清理临时文件，清理失败单独提示；fdopen 失败也关闭底层描述符。
- 写入比只读预览更保守：拒绝 ..、相对路径任一段符号链接、多个硬链接、不可写或特殊权限位的文件；不创建新目标、不删除文件。空文本表示保留空文件。
- 初版面向可信项目，不承诺最后检查与替换之间无竞争窗口、不保留属主/ACL/扩展属性，不保证崩溃后的目录持久性。原子替换防止普通写入中途失败留下半截目标，不是并发恶意文件操作的沙箱。
- 本步仅 Python 接口，尚不注册模型工具或改变主 CLI/Session；后续先确定有写入副作用时的失败历史策略，再接入模型。测试只使用临时项目、可控回调和终端输入替身，不调用模型。


## 第八阶段第三步：模型编辑与有影响的停止交接

- 注册 `edit_file(relative_path, old_text, new_text)`，只接受三个字符串；模型不能传根目录、确认函数或 confirmed。复用预览及写入接口，应用通过 `edit_confirm` 参数提供确认回调；缺失时默认拒绝。主 CLI 显式传 `permissions.confirm_edit`，补充替换文本及写入结果发送提示。
- `ToolResult` 增加 denied/skipped 状态和内部 changed_path：只有应用明确返回 applied 才标记写入，changed_path 不由模型参数设置。普通错误可继续纠正；用户拒绝立即停止本轮，不续问或执行剩余批次。批量分发辅助函数同样遵守拒绝停止。
- 成功轮次仍整体保存并提交旧历史裁剪；纯只读失败保留原行为。有实际写入、批准后中断导致写入不确定或用户拒绝的停止，必须保存完整 user/assistant/tool 消息及本地 assistant 程序停止说明，此时不裁剪旧历史。未完成请求补 skipped 结果，不执行工具，不留下悬空请求。
- `AgentResult` 增加 written_paths、uncertain_paths、history_saved。明确已写入路径不会自动回滚；批准后编辑调用内部中断保守报告不确定并要求重新读取；明确 applied 后的续问中断按已知写入处理。`AgentInterrupted` 继承 KeyboardInterrupt，携带交接结果，CLI 打印后退出。
- 程序停止说明以 `MiniCode 程序记录：` 开头，应用规则标明其来源及未完成含义。历史仅在内存，仍受后续成功裁剪、clear、退出影响，不提供持久审计或崩溃恢复。文件写入不因丢弃/清空历史自动撤销。
- 离线验收：编辑/读取/回答的模型闭环、每次确认、拒绝停止、模型错误及各预算后的写入交接、批准前后中断、完整协议与下一轮历史、CLI 交互及 clear 不回滚。真实模型 API、命令、自动重试或回滚不在本步范围。


## 第九阶段第一步：独立命令执行与逐次确认

- 新增 `tools/command.py`，提供 `run_command(project_root, argv, *, relative_cwd=".", timeout_seconds=30, confirm=None)`；当前仅支持 POSIX。使用不可变 `CommandRequest` 交给应用确认，模型和命令输出不能提供授权。`permissions.confirm_command` 展示实际参数、工作目录、超时及副作用说明，y/yes 批准，EOF/空输入拒绝，中断传播。
- argv 接受列表或元组，1–128 项、合计至多 16 KiB UTF-8；程序名非空，参数无空字节。目录拒绝绝对路径、..、越界和默认敏感路径，解析真实目录并在确认后复核，不承诺防御恶意并发替换。执行使用确认前复制的参数，不受调用者列表变化影响。
- 同步 `Popen(shell=False, start_new_session=True)`，关闭 stdin，继承当前环境。默认 30 秒，允许 1–120 整数秒；selectors 同时排空双流，合计保留前 32 KiB 原始字节，继续丢弃超额内容，返回截断标记。UTF-8 解码替换无效字节，解码后重新编码不承诺同一字节硬上限。
- `CommandResult` 返回 denied/exited/timed_out、returncode、stdout、stderr、output_truncated；非零退出仍是 exited，调用者判断失败。超时返回截止时已收集的数据；主进程退出但后代持管道仍受原截止时间约束。正常、超时和异常路径清理同组后代并回收直接子进程；收集错误抛 CommandError，中断清理后传播。进程组不能终止主动逃离会话的后代。
- 仅约束启动目录，不限制程序对外部文件、网络或环境的访问，不提供沙箱，不自动重试或回滚。第一步不注册模型工具、不接主 CLI、不变更 Session；下一步必须扩展命令副作用和中断的停止交接，不能把命令已执行等同于任务完成。
- 验收覆盖拒绝零执行、双流与退出码、参数及路径边界、每次确认、无 shell 展开、大量输出与精确上限、超时进程组清理、输出收集失败和 Ctrl+C 回收，以及原功能回归。仅使用临时项目和本地 Python 子进程，不访问真实模型 API。


## 第九阶段第二步：模型命令接入与停止交接

- 注册 `run_command(argv, relative_cwd=".", timeout_seconds=30)`，仅接受这三个字段，沿用 JSON 重复键及对象校验；底层接口再次校验类型、范围及路径。`command_confirm` 由应用传入，模型不得设置授权；主 CLI 使用 `permissions.confirm_command`，首次请求前告知参数与双流输出可能发送到模型服务。
- `ToolResult` 新增内部 command_record；程序以 `CommandRecord` 记录不可变实际命令、cwd、timeout、outcome 和 returncode，不根据模型参数或回答填充执行记录，也不推断修改了哪些文件。工具回传上述元数据及双流和截断标记；退出码 0 且 exited 才为 success，非零、超时、收集失败为 error。拒绝为 denied，停止整轮并补齐剩余批次 skipped；普通错误可续问，但后续操作须重新确认。
- `AgentResult.commands` 在成功和停止时都返回命令记录。outcome 为 exited/timed_out/unknown；收集错误通过 `CommandError.started` 区分启动前后，明确启动失败不记录执行影响；批准后中断而无明确结果保守报告 unknown，即便中断发生在 Popen 启动窗口也不声称未执行。
- 命令非零或超时前也可能有副作用，因此有命令记录的停止保存完整当前轮、程序停止说明和旧历史，不提交已省略的历史裁剪。未知请求结果补 error，后续未执行请求补 skipped；中断通过 AgentInterrupted 交接，底层先清理进程组，CLI 打印后退出。正常最终回答仍保存整轮并提交裁剪，CLI 同时展示实际命令记录。
- 工具输出和文件内容不能授予权限；系统规则约束模型不得自主删除文件、提交或推送 Git，不在参数中放密钥。执行层仍只是逐次确认的可信命令接口，不做通用 shell/解释器行为识别或沙箱隔离，不撤销副作用，不新增自动重试、持久化审计或第十阶段修复控制器。
- 离线验收：模拟模型配合真实临时目录命令验证完整回传和后续历史、字段注入、拒绝停止、逐次确认、输出伪装授权、非零/超时副作用、模型错误及各预算停止、批准前后中断与进程回收、混合编辑/命令交接；CLI 覆盖真实确认函数及真实标准输入。真实模型 API 单独验证。
