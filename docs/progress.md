## 第七阶段第二步——上下文限制（已完成）

目标：在每次模型请求前限制消息和工具说明的总字节量，按完整历史轮次裁剪，保证工具请求与对应结果完整；不加入 tokenizer、摘要、编辑或命令工具。

完成内容：

- 新增 `context.py`：`context_bytes()` 计算包含 messages 和 tools 的紧凑 UTF-8 JSON 字节，默认上限 128 KiB；包括系统规则、用户输入、工具请求/结果、工具说明、转义及历史省略提示。不是 token 计数或整个 HTTP 请求体大小，不包含响应。
- `select_context()` 从最早历史整轮开始移除，保留最新连续历史和当前轮全部消息；当前轮本身仍超限时抛出 `ContextLimitError`，在下一次网络请求前停止，不裁剪文件或拆散工具消息。
- `Session` 按成功轮次分组保存，保留原扁平消息接口及深拷贝行为。只有成功记录本轮时，才同时移除本轮请求已省略的旧轮次；失败、停止或中断保留原历史。
- `run_agent()` 每次请求前检查上下文，同一轮后续请求不重新加入已省略历史。Python 接口可传 `max_context_bytes` 正整数；`AgentResult.omitted_history_turns` 和 CLI 展示省略数及本地历史的最终处理方式。
- 更新 README 和设计，明确字节预算、整轮裁剪、超限处理、直接调用底层模型接口的边界。最终回答在请求后保存，因此不承诺进程内存硬上限。
