## 当前任务：第三阶段

目标：保存本次运行中成功的问答，后续问题携带历史，并支持清空。

完成内容：

- 新增 `session.py`：`Session.messages_for()` 构造“历史副本＋当前问题”；`record_turn()` 在成功后保存用户和助手消息；`clear()` 清空历史。
- `llm.py` 的 `ask_model()` 改为接收完整消息列表，不自行保存历史；保留之前的 HTTP、响应、代理配置和缺少 SOCKS 依赖错误处理。
- `cli.py` 每次启动创建独立会话；普通输入经过配置读取、消息构造和模型调用后，才记录整轮。增加 `/clear`，清空时不读取配置、不调用模型。
- 新增会话测试，更新模型和 CLI 测试；通过 MockTransport 集成测试直接检查实际请求中的历史、失败后继续和清空行为。
- README 补充多轮说明和手动验收示例，设计文档补充第三阶段验收条件。

验收条件：

- 第二轮请求按顺序包含上一轮问题、回答和当前问题。
- 请求或配置失败不保存未完成问答，之前成功的历史仍可用于后续请求。
- `/clear` 后下一次请求只包含新问题；允许反复清空空会话。
- 空白、退出和清空命令不进入历史。
- 每次启动从空会话开始；不写入磁盘，不恢复上次会话。
- 自动化测试无需网络、真实密钥或用户 `.env`。

## 用户可执行的多轮验证

1. 保留已填写的 `.env`，激活虚拟环境，在项目根目录执行 `python -m minicode`。
2. 输入“请记住暗号：紫色河马739”，再问“我刚才告诉你的暗号是什么”。确认模型能够利用历史回答。
3. 输入 `/clear`，再问暗号，检查新请求不再带上旧历史；模型回答有随机性，精确请求内容由离线测试验证。
4. 退出并重启，检查会话重新开始。真实验证结果与离线测试分开记录，不粘贴密钥。
