## 当前任务

目标：让终端将当前问题发送到 DeepSeek，并展示回答或清楚的错误提示。

范围与实现：

- `config.py`：用 python-dotenv 读取当前工作目录的 `.env`，环境变量优先，不搜索父目录；校验密钥、模型、HTTPS 基础地址与网络操作超时。配置对象的文本表示隐藏密钥。
- `llm.py`：HTTPX 同步请求 `/chat/completions`，默认模型 `deepseek-flash`，关闭流式和思考模式，最大输出 1024 tokens。每次只发送当前问题，不自动重试。
- `cli.py`：读取输入 → 加载配置 → 请求模型 → 展示回答；配置或模型错误后继续等待，输入和请求阶段的 Ctrl+C 均正常退出。
- `.env.example`：空密钥模板，由用户自行复制为 `.env` 并填写。没有创建、读取或覆盖用户的真实密钥文件。
- 测试隔离当前目录和 DeepSeek 环境变量，使用 HTTPX MockTransport 模拟请求，并禁止进程内真实 HTTP 访问。
- README 补充配置与实际运行步骤；设计文档记录已确定的模型接口、依赖选择和第二阶段验收条件。

验收条件：

- 当前问题可以转换为规范请求，模型的正常文本回答可以展示。
- 空白、退出不调用模型；每次问题互相独立。
- 缺少密钥、配置无效、网络超时、服务错误、无效响应、空回答和非正常结束都有明确提示，不显示密钥或原始服务错误内容。
- 自动化测试无需网络、真实密钥或本地 `.env`；真实 API 验证单独进行。
